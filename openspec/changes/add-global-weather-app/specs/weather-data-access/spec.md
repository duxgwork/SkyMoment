# Spec Delta

## Purpose

为匿名天气查询提供一致的数据接入和故障语义，约束客户端凭据、请求重试、数据有效性和来源使用方式，并以真实账户和大陆海外网络的验证记录判断和风天气能否作为首版主数据源，避免把文档支持误当作实际可用。

## ADDED Requirements

### Requirement: 主数据源验证与上线前置条件
系统 SHALL 优先以和风天气作为主数据源，只有地点搜索、当前天气、七日预报、账户授权及大陆海外网络验证均通过后，才能宣称真实服务验收通过。没有凭据或测试环境时 SHALL 标为未验证；失败时记录阻塞项，不擅自更换供应商或缩减县区/七日要求。

#### Scenario: 文档支持但未发出真实请求
- **WHEN** 开发者只确认官方文档描述了所需能力
- **THEN** 验证记录标注“文档支持，实测待完成”，不能声明 API 集成或地区覆盖已通过

#### Scenario: 实测通过
- **WHEN** 验证矩阵中的中国县区、海外地点、三种语言及大陆海外网络均返回符合要求的数据，并确认账户额度和使用条件
- **THEN** 验收记录保存测试时间、网络区域、接口版本、非敏感结果摘要和通过结论，不保存 Key 或完整 GeoAPI 响应

### Requirement: 匿名直连与凭据隔离
系统 SHALL 通过 HTTPS 直连账户专属 API Host，并由开发者配置凭据，最终用户无需输入 Key。凭据不得提交到代码仓库、出现在日志或错误页面；缺少有效配置时 SHALL 明确提示服务配置不可用而不反复请求。交付说明 MUST 披露客户端内凭据可被提取，限制和混淆不构成秘密保护保证。

#### Scenario: 缺少配置
- **WHEN** 构建或运行环境没有必要的 API Host 或凭据
- **THEN** 发布构建校验失败，开发运行模式显示可识别配置错误，不把配置错误当作网络失败或空天气

#### Scenario: 鉴权失败
- **WHEN** 服务拒绝凭据
- **THEN** 用户看到本地化的服务暂不可用提示，不看到凭据、原始鉴权内容或登录要求，应用不自动循环重试

### Requirement: 数据结果与错误分类
系统 SHALL 区分成功有数据、成功无数据、地点不支持、网络/超时、鉴权/额度/限流、服务端故障及响应格式异常。空数据不得由任意 HTTP 错误推断；HTTP 成功但载荷包含失败码也 SHALL 识别为失败，格式异常不得伪装成功。

#### Scenario: 地点不可用与错误参数
- **WHEN** 服务分别返回明确的无此地点错误或普通错误参数响应
- **THEN** 前者提示无匹配或地点不支持，后者提示服务请求失败，不把所有 400 响应统一显示成空数据

#### Scenario: 格式错误
- **WHEN** 服务响应损坏、类型不符或无法解析
- **THEN** 该区域显示数据异常及可用的恢复入口，其他成功区域继续显示

### Requirement: 有界请求与取消
系统 SHALL 对请求设置有限超时，所有加载最终可结束。仅临时网络故障和可恢复服务故障允许有限自动重试；鉴权、配置、额度不足和解析错误不自动重试。限流 SHALL 遵守服务返回的等待时间或本地冷却策略，禁止立即连续重试；用户切换查询后旧请求不得覆盖新状态。

#### Scenario: 持续超时
- **WHEN** 网络持续不可达
- **THEN** 在有限请求尝试后结束加载，显示超时或网络错误和重试入口，不无限请求

#### Scenario: 触发限流
- **WHEN** 服务返回限流及等待时间
- **THEN** 显示稍后再试，在等待期内重复点击不产生新请求

### Requirement: 数值与数据归属校验
系统 SHALL 将响应转换为明确单位和地点归属的数据，保留有效零值，缺失或非法字段显示占位，禁止伪造默认温度、湿度或风速。湿度必须处于 0–100%，风速不得为负；无法确认日期、地点时区或单位的数据不得以完整成功呈现。

#### Scenario: 非法数值
- **WHEN** 响应含超出范围的湿度、负风速或未知温度单位
- **THEN** 对应指标显示不可用，保留其他有效指标并标示部分数据缺失

### Requirement: 地理信息仅限当前使用
系统 SHALL 只在当前交互会话保留显示和请求必要的地理信息，不建立持久搜索历史、GeoAPI 响应缓存、离线城市索引或包含地理响应的日志。首版不提供持久化天气缓存；当前页面已有天气可在刷新时暂存并显示其原获取时间。

#### Scenario: 搜索后退出进程
- **WHEN** 用户完成搜索且应用进程结束
- **THEN** 磁盘、备份、崩溃附件和 HTTP 缓存中不存在本次 GeoAPI 返回的地点记录，下一次启动重新搜索

### Requirement: 数据来源随展示保留
系统 SHALL 展示和风天气名称及官网链接，并把响应携带的归因声明与对应天气一起提供；不删除数据源要求附带的声明。搜索页面使用地理服务时也 SHALL 提供清晰的服务来源标注。

#### Scenario: 刷新后归因变化
- **WHEN** 新天气响应包含不同的归因声明
- **THEN** 展示信息随新响应更新，仍可清楚访问来源，日志与错误内容不代替页面归因
